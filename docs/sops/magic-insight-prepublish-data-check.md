# Magic Insight 研究报告 · 发布前数据核查

> **适用范围**：所有以 Magic Insight 数据研究院名义对外发布的研究报告（Vol.xx 系列），
> 以及任何要发给客户 / 合作方 / 投资人的、带数字的研究类文档。
>
> **强制程度**：`npx vite-node scripts/magic-insight-prepublish-check.ts` 有 blocking 项时**不得发布**。
> 这不是"建议看一眼"的清单——2026-09-03 的事故证明，靠自觉的清单等于没有清单。

---

## 为什么存在（2026-09-03 事故）

两份对外研究报告（Vol.01 中国入境游、Vol.02 中国→澳洲物流）在起草时**未跑任何一次实时数据查询**——
未调 DataForSEO、未做 WebSearch、未抓 ABS / NIA / Auspost 任何一个数据源——
却给自造数字配上了权威来源标注：

- `ABS · International Trade in Goods`
- `Google Ads Keyword Planner`（一张 10 行关键词表，搜索量与 CPC 全部未拉取）
- `国家移民管理局`
- `Trip.com Group 财报`
- 一份声称"抽样约 40 家、审计时间 2026 年 8 月"的审计——**该审计从未执行**

直接违反 [CLAUDE.md](../../CLAUDE.md) 铁律 8：
「搜索量 / KD / 点击数**必须**来自 DataForSEO 或 GSC，不能估不能编」。

更要命的是**修正版里又新引入了一个 10 倍单位错误**（`A$82.6 billion` 写成「A$82.6 亿」，应为 826 亿）——
说明"这次我小心一点"根本不是一种可靠的控制手段。

事后 34 个 agent 的全量核查还发现了第三类问题：**报告自己写了自证清白的句子**
（"所有数字均可反向溯源"、"未采购任何付费数据订阅"），
主动邀请读者去核对，而核对一定失败。**这是全案最大的信誉风险，比数字错本身更严重。**

---

## 三类失败模式（决定了闸门怎么设计）

| 类型 | 本次实例 | 机器能不能管 |
|---|---|---|
| **A · 编造** — 数字凭空生成 + 挂权威来源 | 关键词表、40 家审计 | ❌ 文本分析看不出来，只能靠 **receipt/产物** 强制 |
| **B · 机械错** — 换算、单位、口径混用 | `A$82.6 亿` vs `A$82.6 b` | ✅ 完全可自动拦截 |
| **C · 措辞风险** — 自证清白、装饰性引用 | "所有数字均可反向溯源"、列了 NAB 却没用 | ✅ 可自动拦截 |

**闸门只能覆盖 B 和 C。A 类只能靠"拿不出凭证就不许写"这条硬规矩。**
这也是为什么下面第 1 步不是"跑脚本"而是"先备齐凭证"。

## 发布前流程

### 第 1 步 · 备齐凭证（人做，机器只验有没有）

| 内容类型 | 必须有的凭证 | 怎么拿 |
|---|---|---|
| 搜索量 / CPC / KD / SERP 占位 | DataForSEO 拉取结果文件 | `src/lib/dataforseo/search-volume.ts` · `serp.ts` |
| 声称做过的调研 / 抽样 / 走访 | 名单 + 评分表 + 原始记录 | 真做过就一定有；拿不出就**删掉这段** |
| 官方统计数字 | 一手页面 URL（不是转述博客） | WebFetch 原始政府/机构页面 |
| 行业数据商数字 | 报告名 + 期数 + 页码或链接 | 公开报告需可点开验证 |

> **最容易翻车的地方**：拿到一个二手转述（新闻稿、博客、其他报告）就当一手源。
> 本次核查发现多处"找到的是重复引用它的博客，不是发布它的机构"。
> **判据：能不能点开看到发布方自己的页面。**

### 第 2 步 · 跑机械闸

```bash
npx vite-node scripts/magic-insight-prepublish-check.ts -- <报告.html> \
  --receipt receipts/dataforseo-2026-09-03.json \
  --artifact docs/research/au-freight-audit-2026-08.csv \
  --source "Australian Bureau of Statistics" \
  --source "Australia Post eCommerce Report"
```

有 blocking 时退出码为 `1`，可直接挂进 CI 或发布脚本。

**七条规则**：

| 规则 | 级别 | 拦什么 |
|---|---|---|
| `scale-conversion-mismatch` | 🔴 拦截 | 中英数量级换算不自洽（1 b = 10 亿；1 m = 100 万） |
| `scale-unit-unpaired` | 🟡 提醒 | 货币金额只写"亿/万"不给原始口径，无法机械校验 |
| `self-certifying-claim` | 🔴 拦截 | "所有数字均可反向溯源"这类全局承诺 |
| `fieldwork-without-artifact` | 🔴 拦截 | 声称做过调研但没登记产物 |
| `search-metric-without-receipt` | 🔴 拦截 | 搜索类指标没有实时拉取凭证（铁律 8） |
| `orphan-source` | 🟡 提醒 | 来源清单列了但正文没有数字用到它 |
| `untiered-headline-figure` | 🔴 拦截 | 头条数字附近没有数据分层标注 |

### 第 3 步 · 人工过四个机器管不了的问题

机械闸全绿**不等于**可以发。以下四条必须由人过：

1. **这个数字是真的吗** — 抽查 3–5 个关键数字，亲手点开一手源核对一遍。
   优先抽查"支撑核心结论的那几个"，不是随机抽。
2. **口径对得上吗** — FY 还是 CY？货物还是货物+服务？入境游客还是出入境人次？
   本次事故里 `A$120b` 是"货物+服务"，被当成"纯商品"用；
   `29.2M` 既不是入境游客数（26.9M）也不是出入境人次（64.9M），两头不靠。
3. **同一件事在文档里说了两遍吗，两遍一致吗** — 本次事故里澳洲免签生效日在时间轴写 2024-07、
   在客源表写 2024/11，**同一份报告自相矛盾**。
4. **删掉所有编造数字后，论点还站得住吗** — 如果论点本身依赖某个拿不出凭证的数字，
   那不是"改个数字"的问题，是**这一节要重写或删掉**。

### 第 4 步 · 数据分层标注

每个显著数字必须标明属于哪一类：

| 标注 | 含义 |
|---|---|
| `已核实` | 附一手来源链接，本人点开核对过 |
| `行业口径` / `货代口径` | 来自行业公开报价或数据商，非官方统计 |
| `推算` | 基于已核实数字的换算，标明算法 |
| `判断` | 本院综合判断，**明确不是数据** |
| `待核` | 尚未核实，仅作参考——**对外版本不应出现** |

## 措辞红线

**禁止**出现在对外报告里的句式：

- ❌ "所有数字均可反向溯源"
- ❌ "全部数据均可独立验证"
- ❌ "未采购任何付费数据订阅"（同时暗示"全靠公开源"和"因此可核对"）
- ❌ "每一个数字都能追溯到一手来源"

**为什么禁**：这类句子把举证责任反过来压在自己身上，
读者只要找到**一处**不成立，整份报告的可信度就归零。
正确做法是**逐条标注分层**，让读者自己看哪些是硬数据、哪些是判断。

**替代写法**：

> 本节标注为「已核实」的数字附一手来源链接；标注为「推算」的为本院基于公开数据的换算，
> 算法见脚注；标注为「判断」的为综合判断，不构成数据。

## 复用边界（Reuse First）

- **复用** [`src/lib/market-intel/grounding.ts`](../../src/lib/market-intel/grounding.ts) 的 `extractNumbers`
  —— 已实现的数字抽取，不重复造。
- **补充** 该模块注释里明确列为"不覆盖的已知边界"的那块：中英数量级换算
  （它的原话是「$150 million 如果被摘要成 1.5亿美元，数字形态变了，会被误判」）。
  那恰好是本次事故的错因。
- **不做** 完整事实核查 —— 那需要 receipt 和人工，不是文本分析能解决的。
