# SOP — 新客户 Meta 广告户开通与授权（通用路径）

> **目的**：任何新客户要把 Meta（Facebook/Instagram）广告户交给 Magic Engine 代管/代投时，都走这一条路径，不因客户不同而另起一套流程。
> **执行人**：客户方 / 客户方所在的 PM（必须是该广告户的 Business Manager 管理员本人操作，ME 不能代做——这是 Meta 官方要求，授权必须由账户所有者亲自完成）
> **耗时**：5-10 分钟
> **前置**：操作人已经是目标客户 Business Manager 的 Admin
> **验证**：2026-09-13 用 Magic Picks 实测走通，以下是实测确认可行的路径

本文档取代 `meta-system-user-token-setup.md` 里"新建系统用户 + 挂应用"那条路——那条路在**新建的业务账户上会卡死**（系统用户必须先关联一个应用，而关联应用的唯一入口是"转移应用所有权"，新业务账户走不通，2026-09-13 Magic Picks 接入时实测卡死）。新客户一律走下面这条更简单、Meta 更推荐的"业务账户互相合作伙伴"路径。

---

## 一条原则：不建系统用户、不碰应用，直接"业务账户对业务账户"共享

Meta 的业务账户（Business Portfolio）本身就能互相"合作"，一方把自己的资产（广告账户、公共主页）共享给另一方，对方的人员/系统用户就能直接管理，全程不涉及"新建应用""新建系统用户"这些容易卡死的步骤。

**Magic Engine 自己的业务账户编号**：`1265811139097132`（登录 business.facebook.com 用 Magic Engine 身份查到的，以后所有客户都填这一个号）

## 二、操作步骤（客户自己做，5分钟）

1. 打开 https://business.facebook.com，顶部切到**客户自己的**业务账户（不是 Magic Engine 的）
2. 左侧「用户」→「合作伙伴」
3. 右上角「+ 添加」**右边的小箭头**（不是直接点添加按钮）→ 会弹出两个选项，**必须选第一个**：
   - ✅ **「允许合作伙伴访问你的资产」**（把你自己的资产分给对方）——选这个
   - ❌ 「请合作伙伴为你分配其资产」——**不要选**，这个是反过来问对方要资产，2026-09-13 第一次操作时选错过这个，导致弹出的资产选择器里出现的是 Magic Engine 名下**其他客户**的主页（等于要把别的客户的资产分给这个新客户），非常危险，当场撤销重来
4. 「业务资产组合编号」填 `1265811139097132`
5. 下一步选权限：勾选「广告账户」，给**完全控制**；如果也想让 Magic Engine 帮忙发布内容到主页，「公共主页」也勾上给完全控制
6. 「Partner's credit line」这一步跟额度/付款方式有关，选 **Not now** 跳过——客户自己的广告还是用客户自己的付款方式，不用共享
7. 检查无误后确认发送

## 三、Magic Engine 这边确认接收（子牙/PM 代做即可，不需要客户操作）

1. 登录 Magic Engine 自己的业务账户（`1265811139097132`）→「合作伙伴」，能看到这个客户带着「Partner request received」标签
2. 点进去，右上角「回复申请」→「开始」→「下一页」（审核客户信息）→ 这一步**不会**弹出要挑选 Magic Engine 自己资产的选择器（那是走错方向才会出现的），走到底提交
3. 确认后，客户的合作伙伴卡片里「分配给你的资产」标签页应该能看到广告账户，权限显示「完全访问权限」——这就是成功的标志

## 四、把广告户登记进数据库

在 Magic Engine 自己业务账户的「账户」→「广告账户」列表里能直接看到新客户的广告户（会带着"归 XX 所有"的标签），点进去复制账户编号，登记进 `client_meta_ad_accounts` 表：

```sql
INSERT INTO client_meta_ad_accounts (client_id, ad_account_id, label, is_primary)
VALUES ('<clients.id>', 'act_XXXXXXXXX', '<客户名> 主广告户', true);
```

## 五、如果以后要让服务器自动发广告（不只是人工在 Ads Manager 里操作）

上面的步骤只解决"人能不能管"，不解决"服务器代码能不能自动调 API"。如果某个客户需要 ME 后台自动生成/自动投放（不是人工操作），才需要走 `meta-system-user-token-setup.md` 里"生成永不过期令牌"那部分——但那个令牌应该在 **Magic Engine 自己的业务账户**下生成（Magic Engine 自己名下应该已经有可用的系统用户，用来管所有通过本 SOP 共享进来的广告户），不需要在每个新客户的业务账户里各建一次系统用户。这部分待子牙确认 Magic Engine 自己业务账户下系统用户的现状后再补完。

## 常见问题

**Q1：这条路和"新建系统用户+挂应用"那条路有什么区别？**
A：系统用户路径是"在客户的业务账户里，为 Magic Engine 单独开一个身份，还要挂一个应用才能生成令牌"——每个客户都要重复一遍，而且新业务账户会在"挂应用"这步卡死。合作伙伴共享路径是"客户把资产直接共享给 Magic Engine 整个业务账户"，不涉及应用，不涉及系统用户，5分钟搞定。

**Q2：选错方向（选成"请合作伙伴为你分配其资产"）已经发出去了怎么办？**
A：回到发起方（客户）业务账户的「合作伙伴」页面，点这条记录，点「拒绝」把它拒掉，重新按上面步骤二第3步选对方向再发一次。已经拒绝的不会留下任何权限。

**Q3：客户还没有广告户 / 主页，怎么办？**
A：先在客户自己的业务账户里新建（「账户」→「广告账户」/「公共主页」→「添加」），归属必须是客户自己的业务账户，不能挂在 Magic Engine 名下——见 `CLAUDE.md` 铁律 8「客户营销落地页必须建在客户自己的域名」同理，广告户/主页所有权也必须是客户的，Magic Engine 只是被授权的代管方。
